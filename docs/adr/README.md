# Decisões de arquitetura

Não há decisões novas de banco, storage ou orquestração nesta fase. A stack observada está descrita na [auditoria do frontend](../systems/frontend.md); sua existência não implica uma escolha para os futuros serviços de dados.

Nomear registros sequencialmente: `0001-assunto.md`. Cada ADR deve conter status (proposto, aceito, rejeitado ou substituído), data, contexto, alternativas, decisão, consequências e evidências relacionadas. Decisões substituídas devem apontar para o novo registro.

As questões abertas estão na [arquitetura técnica](../03-technical-architecture.md) e na auditoria. Avaliar armazenamento após a prova de conceito, conforme fases 5 e 6 do [roadmap](../04-roadmap.md).
